## Назначение

Марсоходы NASA передают снимки с бортовых камер, и они доступны публично с указанием аппарата, даты
съёмки и камеры. Приложение делает из этого набора данных просмотрщик: выбирается один из четырёх
аппаратов (Perseverance, Curiosity, Opportunity, Spirit) и дата, после чего страница показывает
сетку снимков за эти сутки с подписью камеры, а по клику открывает снимок целиком с переходом к
соседним кадрам и возможностью открыть оригинал.

Страница статическая: HTML, CSS и JavaScript без этапа сборки, состояние интерфейса описано одним
экземпляром Vue, библиотеки подключены с CDN.

## Получение данных

Прямое обращение к API из статической страницы упирается в ключ доступа: в клиентском коде он виден
любому посетителю, а квота на запросы общая для всех, кто этим ключом воспользуется. Поэтому запросы
уходят на промежуточный HTTP-сервис, повторяющий формат ответа: массив снимков, у каждого адрес
изображения и полное название камеры.

Адреса изображений в ответе указаны по протоколу http, тогда как сама страница открывается по https.
Браузер блокирует такое смешанное содержимое, поэтому схема в адресе заменяется перед подстановкой
в разметку.

## Границы дат по аппаратам

Opportunity прекратил передачу 10 июня 2018 года, Spirit 22 марта 2010 года, действующие аппараты
ограничены текущей датой. Приложение хранит верхнюю границу для выбранного аппарата, пересчитывает
её при смене марсохода и зажимает дату, введённую вручную.

Ограничение нужно не для строгости, а для читаемости результата: за пределами срока работы аппарата
ответ всегда пуст, и без него пустая выдача выглядела бы отказом приложения, а не отсутствием
съёмки.

## Лента дат на canvas

Переключение даты сделано лентой из трёх позиций: предыдущие сутки, выбранные и следующие. Под
подписями расположен слой canvas, на котором средствами CreateJS нарисованы линия и три круга, а
отрисовка идёт по тику с частотой 60 кадров в секунду. Наведение на позицию запускает пульсацию
круга, переход к соседней дате анимируется смещением всей группы через GSAP.

Два момента определяют поведение ленты:

- **Замыкание координат.** По ходу анимации круг, ушедший за край, переносится на противоположную
  сторону, поэтому лента прокручивается в обе стороны без видимых концов, оставаясь тремя объектами.
- **Блокировка на время перехода.** Пока анимация не закончена, обработчик установлен в состояние
  блокировки и новые переключения игнорируются. Без этого серия быстрых нажатий рассогласовала бы
  положение ленты с датой, по которой запрашиваются снимки.

## Сетка миниатюр

Снимки с разных камер отличаются пропорциями, а их размеры неизвестны до загрузки. Плитка сетки
получает фиксированную высоту сразу, а после загрузки изображения высота пересчитывается по
отношению его сторон, поэтому сетка не перестраивается скачками по мере поступления файлов. При
изменении размера окна пересчёт повторяется для всех плиток.

За сутки один аппарат передаёт до нескольких сотен кадров, поэтому вывод постраничный, по двадцать
снимков, с номерами страниц под сеткой.

## Полноэкранный просмотр

Снимок открывается поверх страницы после загрузки полного изображения, а не сразу по клику: его
положение вычисляется по фактическим размерам, чтобы кадр появился уже отцентрованным. Вписывание
идёт по той стороне, которая выходит за пределы контейнера, и повторяется при изменении размера
окна. В этом режиме доступны переход к предыдущему и следующему снимку, счётчик позиции и открытие
оригинала в новой вкладке; клик вне изображения закрывает просмотр.

## Устройство страницы

Отказ от этапа сборки упростил развёртывание, но развёл состояние по двум механизмам: данные и
разметка описаны реактивным состоянием Vue, а анимация ленты работает императивно на canvas и
хранит своё состояние в отдельных объектах. Связаны они через наблюдение за одним значением
положения. Для страницы такого объёма это приемлемо, но с ростом числа анимированных элементов
границу пришлось бы проводить строже.

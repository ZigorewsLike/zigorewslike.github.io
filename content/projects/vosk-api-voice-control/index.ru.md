## Задача

Anthropic Principle — космический симулятор на движке Unigine с управлением кораблями и
флотом. Игрок переключает режим камеры, задаёт скорость, отдаёт команды выбранным
кораблям — всё это разложено по горячим клавишам и элементам интерфейса.

Добавлена альтернатива клавиатуре: те же действия вызываются голосом. Распознавание
выполняется полностью локально.

Проект закрытый, исходники недоступны. Ниже описано устройство подсистемы.

## Общая схема

Управление построено по принципу push-to-talk: игрок удерживает кнопку (Numpad 0),
говорит и отпускает. Пока кнопка нажата, звук с микрофона захватывается и потоком
подаётся в сессию распознавания. На отпускании сессия формирует итоговую фразу, она
нормализуется и сопоставляется с реестром команд; первый подошедший шаблон вызывает
привязанное к нему действие.

```
[ Down PTT ] → захват звука (NAudio) → блоки 16 000 байт → Vosk-сессия
[ Up PTT ]   → финализация фразы → нормализация текста → подбор шаблона → команда
```

Захват, построение распознавателя и финальный пересчёт языковой модели — операции
разной стоимости, поэтому они разнесены по потокам, чтобы нажатие и отпускание
кнопки не подвешивали основной поток ввода.

## Захват и подача звука

Звук захватывается через NAudio (`WaveInEvent`) в фиксированном формате 16 кГц, моно,
PCM16 — приведение частоты и числа каналов берёт на себя микшер Windows.

Vosk принимает не отдельные драйверные буферы, а блоки фиксированного размера, поэтому
входной звук накапливается в буфере `FeedChunkBytes = 16000` байт (8000 отсчётов
int16 при 16 кГц ≈ 500 мс) и подаётся в сессию по мере заполнения. Обработчик работает
на потоке захвата NAudio под блокировкой сессии:

```csharp
private void _OnAudio(byte[] buffer, int count)
{
    lock (_sessionLock)
    {
        if (_session == null) return;

        int srcOffset = 0;
        while (srcOffset < count)
        {
            int copy = Math.Min(count - srcOffset, FeedChunkBytes - _feedBufferLen);
            Buffer.BlockCopy(buffer, srcOffset, _feedBuffer, _feedBufferLen, copy);
            srcOffset += copy;
            _feedBufferLen += copy;

            if (_feedBufferLen >= FeedChunkBytes)
            {
                _session.Feed(_feedBuffer, _feedBufferLen);
                _feedBufferLen = 0;
            }
        }
    }
}
```

## Обёртка над Vosk

Распознавание выполняет библиотека Vosk (пакет `Vosk` 0.3.38). Её типы спрятаны за
интерфейсом сессии, чтобы остальной код не зависел от библиотеки напрямую:

```csharp
public interface ISpeechSession : IDisposable
{
    void Feed(byte[] pcm16Mono16k, int count);
    string PartialText { get; }
    string End();
}
```

Модель (`Vosk.Model`) загружается один раз на язык из `data/sound/vosk_models/<lang>` и
держится в памяти, только пока ассистент включён, — это самый тяжёлый ресурс. На каждую
произнесённую фразу создаётся отдельный распознаватель `VoskRecognizer`:

```csharp
_model = new Model(path);                        // один на язык
// ...
_rec = new VoskRecognizer(model, sampleRate);    // sampleRate = 16000, один на фразу
_rec.SetWords(true);
```

Блоки PCM подаются в `AcceptWaveform`, который возвращает признак конца фразы. Сам текст
Vosk отдаёт JSON-строкой, из которой берётся нужное поле (`text` для итога, `partial`
для промежуточного результата):

```csharp
public void Feed(byte[] pcm, int count)
{
    bool complete = _rec.AcceptWaveform(pcm, count);
    _partial = complete
        ? _ExtractField(_rec.Result(), "text")
        : _ExtractField(_rec.PartialResult(), "partial");
}

public string End() => _ExtractField(_rec.FinalResult(), "text");

private static string _ExtractField(string json, string field)
{
    using var doc = JsonDocument.Parse(json);
    return doc.RootElement.TryGetProperty(field, out var el) ? el.GetString() ?? "" : "";
}
```

## Латентность

Одна сессия соответствует одной фразе. Создание `VoskRecognizer` и финализация через
`FinalResult` (полный пересчёт по языковой модели) — тяжёлые операции, поэтому:

- следующая сессия строится заранее, в фоне, и подставляется на следующем нажатии
  кнопки, чтобы момент начала записи не тормозил;
- финализация после отпускания кнопки откладывается на `CaptureDrainMs = 200` мс, за
  которые до сессии успевает дойти звук, ещё лежащий в очереди буферов драйвера;
- `FinalResult` и освобождение сессии выполняются в фоновой задаче, а готовый текст
  передаётся в основной поток через очередь.

## Нормализация текста и чисел

Выданный Vosk текст перед подбором шаблона приводится к каноничному виду: нижний
регистр, не-буквенно-цифровые символы заменяются пробелами, пробелы схлопываются, строка
обрамляется пробелами (для границ слова в регулярных выражениях). Затем числительные
прописью заменяются на цифры для русского и английского (диапазон 0..9999).

Нормализатор чисел разбирает поток токенов, накапливая разряды единиц/десятков/сотен и
умножители «сто»/«тысяча», и выводит собранное число при разрыве последовательности:
«скорость пять» → «скорость 5», «сто восемьдесят» → «180», «two thousand five hundred»
→ «2500». Так одна и та же команда `скорость {n:int}` принимает и «скорость 5», и
«скорость пять». Не поддержаны отрицательные числа, дроби, порядковые и связки
«и»/«and».

## Команды и шаблоны

Команда — это идентификатор, набор текстовых шаблонов и функция-обработчик. Набор
объявлен статически и регистрируется в реестре команд при инициализации мира:

```csharp
private static readonly VoiceCommandEntry[] _Commands =
{
    new("focus_nearest_player_ship", _ => _FocusNearestPlayerShip(), new[] { "focus", "фокус" }),
    new("ship_move_forward",         _ => _MoveForward(),            new[] { "forward", "вперёд", "вперед" }),
    new("ship_move_backward",        _ => _MoveBackward(),           new[] { "back", "назад" }),
    new("toggle_controller_mode",    _ => _ToggleControllerMode(),   new[] { "mode", "режим" }),
    new("ship_change_speed_steps",   _ChangeSpeedSteps,              new[] { "speed {n:int}", "скорость {n:int}" }),
};
```

Каждый шаблон компилируется в регулярное выражение один раз при регистрации. В шаблон
можно вставлять параметры вида `{имя:тип}` (`int` — целое число, `word` — одно слово);
литеральные части экранируются, между токенами вставляется `\s+`, а всё выражение
обрамляется границами слова, поэтому шаблон `fire` не срабатывает на `firearm`:

```csharp
string body = type switch
{
    "int"  => @"-?\d+",
    "word" => @"\S+?",
    _      => throw new ArgumentException($"Unknown slot type '{type}'..."),
};
// ...
sb.Append("(?<").Append(name).Append(">").Append(body).Append(")");   // именованная группа-слот
// ...
var rx = new Regex(sb.ToString(), RegexOptions.IgnoreCase | RegexOptions.Compiled);
```

Совпавшая группа читается обработчиком через `VoiceArgs`: `args.TryGetInt("n", out …)`
для `int`-слота, `args.GetString(name)` для `word`. Русские и английские шаблоны одной
команды сосуществуют.

Реализованный набор команд привязан к жизненному циклу игрового мира и зависит от
текущего режима управления:

| Команда | Пример фраз | Действие |
| --- | --- | --- |
| Фокус на ближайшем корабле | «фокус», `focus` | Только в стратегическом режиме: наводит камеру на ближайший корабль своей стороны. |
| Смена режима управления | «режим», `mode` | Переключает между стратегическим видом и видом от третьего лица. |
| Движение вперёд / назад | «вперёд», «назад», `forward`, `back` | В виде от третьего лица: шаг изменения желаемой скорости в плюс или минус. |
| Задать скорость | «скорость 5», `speed 5` | Устанавливает абсолютную желаемую скорость; принимает и числительные прописью. |

Обработчики не трогают игровые системы напрямую, а публикуют события движка
(навести камеру, сменить режим, изменить скорость) — так же, как это делают привязки
клавиш. Каждая команда проверяет применимость (режим управления, наличие выбранного
корабля) и молча пропускается, если условие не выполнено. Пример — «задать скорость»:
проверка режима и корабля, чтение слота, публикация события с дельтой до целевого
значения:

```csharp
private static void _ChangeSpeedSteps(VoiceArgs args)
{
    if (!_TryGetControlledShip(out _, out var ship)) return;   // только вид от третьего лица
    if (!args.TryGetInt("n", out int n)) return;
    _EnsureVelocityControl(ship);                              // FORWARD → FORWARD_AND_VELOCITY
    float current = ship.Agent.Decisions.Client.TargetSpeed;
    GR.Get<InputManager>().EventSystem.Publish(new ChangeDesiredSpeedStepArgs { value = n - current });
}
```

## Интеграция с движком

В настройках (`Settings → Audio`) добавлены выбор устройства записи, регулятор
усиления, индикатор уровня, переключатель ассистента и выбор языка. На время загрузки
модели элементы блокируются, ошибка загрузки показывается отдельной строкой.
Отдельное отладочное окно на ImGui ведёт журнал: для каждой фразы — какая команда
сработала либо что совпадения не нашлось.

## Потоки

Работа разнесена по потокам, чтобы захват и распознавание не блокировали игровой цикл:

| Этап | Поток |
| --- | --- |
| Захват звука, накопление блока | Поток захвата NAudio |
| Подача заполненного блока в сессию | Поток захвата (под блокировкой сессии) |
| Построение следующей сессии заранее | Фоновая задача |
| Финализация фразы, завершение и освобождение сессии | Фоновая задача |
| Разбор результата и вызов обработчиков команд | Основной поток |

## Итог

Голосовое управление добавлено как надстройка над существующей системой команд:
распознавание идёт локально и офлайн, новые команды добавляются парой «шаблон плюс
обработчик», а тяжёлые операции вынесены в фон, поэтому запись и распознавание не
влияют на плавность игры. Ограничения текущей версии: настройки звука не сохраняются
между сессиями, язык выбирается вручную, кнопка push-to-talk не переназначается через
интерфейс управления.

## Назначение

Свёртка изображения это взвешенное суммирование окрестности каждого пикселя по заданной матрице
коэффициентов. На ней построены типовые операции обработки: размытие, повышение резкости,
выделение границ. Результат для каждого пикселя вычисляется независимо от остальных, поэтому задача
допускает распараллеливание вплоть до одного потока на пиксель, что делает её показательным
примером расчёта на графическом процессоре.

Приложение даёт этой операции интерфейс: изображение загружается, матрица размером от 3x3 до 9x9
задаётся по ячейкам или выбирается из готовых, результат отображается рядом с оригиналом с
указанием затраченного времени и может быть сохранён.

## Разделение на управляемую и нативную часть

Решение состоит из двух проектов. Ядро CUDA компилируется nvcc в нативную библиотеку
`cudaFanc64.dll`, интерфейс написан на C# под .NET Framework 4.7.2 и Windows Forms.

Граница между средами сведена к двум экспортируемым функциям с простыми типами. Первая возвращает
число доступных устройств CUDA, вторая выполняет свёртку и принимает указатели на изображение, на
матрицу коэффициентов и её размер. Обе объявлены как `extern "C"` с `__declspec(dllexport)`,
поэтому на стороне C# им соответствует объявление `DllImport` без дополнительных обёрток. Массивы
перед вызовом закрепляются в памяти через `GCHandle`, чтобы сборщик мусора не переместил их во
время работы нативного кода, а результат копируется обратно в управляемый массив через
`Marshal.Copy`.

Проверка числа устройств вынесена в отдельную функцию намеренно: она вызывается до расчёта, и
отсутствие подходящей видеокарты приводит к сообщению, а не к отказу при обращении к CUDA.

## Ядро CUDA

На каждый пиксель приходится один поток, его линейный индекс вычисляется из номера блока и номера
потока внутри блока. Поток обходит все коэффициенты матрицы, для каждого получает координаты
соответствующего пикселя окрестности и накапливает взвешенную сумму.

Три решения определяют результат:

- **Края изображения.** Координаты, вышедшие за пределы кадра, зажимаются к ближайшему краю, то
  есть окрестность за границей достраивается краевыми пикселями. Альтернатива в виде пропуска таких
  отсчётов давала бы затемнённую рамку по периметру.
- **Нормировка.** Сумма делится на сумму коэффициентов матрицы, если та отлична от нуля. Без этого
  усредняющее ядро из единиц увеличивало бы яркость кратно своему размеру. Матрицы с нулевой суммой,
  такие как операторы Собеля и лапласиан, обрабатываются без деления.
- **Ограничение диапазона.** Результат приводится к 0..255, поскольку операции выделения границ
  дают значения обоих знаков и с выходом за верхнюю границу.

Время расчёта измеряется событиями CUDA вокруг запуска ядра, то есть отдельно от копирования данных
между хостом и устройством.

## Обработка изображения на стороне C#

Штатные `Bitmap.GetPixel` и `SetPixel` для полного прохода по изображению непригодны: каждый вызов
блокирует и разблокирует данные растра. Вместо них используется класс-обёртка, который держит
закреплённый массив `Int32`, служащий буфером растра, и читает и пишет пиксели прямым обращением по
индексу.

Изображение обрабатывается плитками фиксированного размера, каналы R, G и B передаются в ядро
отдельными вызовами. Такое разбиение ограничивает объём данных, передаваемых на устройство за один
раз, и не требует согласования формата пикселя с нативной стороной: в библиотеку уходит массив
значений одного канала.

## Интерфейс

Сетка полей ввода перестраивается под выбранный размер матрицы, для нечётных размеров центральный
коэффициент по умолчанию равен единице, что соответствует тождественному преобразованию. Готовые
матрицы задают операторы Собеля по осям X и Y, размытие и повышение резкости ядром 5x5 и лапласиан.
Исходное и обработанное изображения показаны рядом, время обработки выводится в строке состояния.

## Ограничения

Расчёт выполняется только на видеокартах NVIDIA, поскольку опирается на CUDA. Плитки
обрабатываются без перекрытия, поэтому краевое условие применяется к границе плитки, а не всего
изображения, и на стыках возможны заметные переходы при матрицах большого размера. Интерфейс на
время расчёта блокируется: вызов нативной функции выполняется в потоке пользовательского
интерфейса.

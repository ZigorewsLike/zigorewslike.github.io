# Портфолио на Flask

Двуязычный (RU/EN) сайт-портфолио: главная страница со списком проектов по
категориям и единый шаблон страницы проекта. Контент хранится в файлах
(Markdown и YAML), база данных не используется. Приложение не хранит состояния,
поэтому сайт можно как обслуживать WSGI-сервером, так и целиком отрендерить в
статику и выложить на GitHub Pages.

Язык задаётся префиксом URL: `/ru/…` и `/en/…`. Корень `/` перенаправляет на
язык по умолчанию.

## Требования

- Python 3.10 или новее (CI собирает на 3.12)
- Зависимости из `requirements.txt`: Flask, python-frontmatter, Markdown,
  PyYAML, Pygments

## Локальный запуск

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows; на Linux и macOS: source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Сайт поднимается на http://127.0.0.1:5000

В dev-режиме (`FLASK_DEBUG=1`, значение по умолчанию) контент перечитывается с
диска на каждый запрос, так что правки в `.md` и `.yaml` видны после обновления
страницы. При `FLASK_DEBUG=0` контент загружается один раз и кэшируется в
памяти.

## Структура

```
portfolio-site/
├── app.py                      # Flask-приложение: роуты, обработка языка
├── config.py                   # пути к контенту, DEBUG, кэш, SITE_BASE_URL
├── freeze.py                   # сборка статической версии сайта
├── requirements.txt
├── portfolio/
│   ├── content.py              # загрузка проектов, профиля и строк интерфейса
│   ├── experience.py           # расчёт периодов и общего стажа
│   └── richtext.py             # Markdown и автоссылки в текстовых полях профиля
├── content/
│   ├── profile.<lang>.yaml     # профиль: контакты, опыт, образование, публикации
│   ├── translations/
│   │   └── <lang>.yaml         # строки интерфейса
│   └── projects/
│       └── <slug>/
│           ├── index.<lang>.md # frontmatter и тело страницы проекта
│           └── assets/         # изображения и видео, общие для всех языков
├── templates/
│   ├── base.html               # каркас: шапка, навигация, переключатель языка, футер
│   ├── index.html              # главная
│   ├── project.html            # страница проекта
│   ├── _project_card.html      # карточка проекта на главной
│   └── 404.html
├── static/
│   ├── css/style.css
│   └── js/filter.js            # фильтр проектов по категориям
└── .github/workflows/pages.yml # сборка и публикация на GitHub Pages
```

## Маршруты

| URL | Назначение |
|-----|------------|
| `/` | редирект на язык по умолчанию |
| `/<lang>/` | главная страница |
| `/<lang>/projects/<slug>/` | страница проекта |
| `/projects/<slug>/assets/<file>` | файлы проекта, общие для всех языков |

Язык извлекается из URL в `g.lang` и автоматически подставляется в `url_for()`,
поэтому view-функции его не принимают. Неизвестный префикс даёт 404.

## Языки

Список языков задаётся словарём `LANGUAGES` в `portfolio/content.py`, язык по
умолчанию константой `DEFAULT_LANG` в том же файле.

Если для языка нет файла проекта или профиля, используется версия на языке по
умолчанию, так что проект не пропадает из локали. Переключатель языка в шапке
ведёт на ту же страницу в другой локали, для поисковых систем проставляются
теги `hreflang`.

Добавление языка (например `de`) требует трёх шагов: запись в `LANGUAGES`,
файлы `content/translations/de.yaml` и `content/profile.de.yaml`, при
необходимости `index.de.md` в папках проектов.

## Профиль

`content/profile.<lang>.yaml` содержит данные для главной страницы.

| Поле | Назначение |
|------|------------|
| `name` | имя, используется в футере и как запасное значение для заголовков |
| `title` | должность или специализация |
| `site_title` | заголовок вкладки браузера, по умолчанию берётся `name` |
| `brand` | подпись логотипа в шапке, по умолчанию берётся `name` |
| `tagline` | короткое описание, попадает в мета-тег description |
| `avatar` | путь относительно `static/`, например `img/avatar.jpg` |
| `email`, `location`, `socials` | блок контактов |
| `experience` | места работы, см. ниже |
| `education`, `publications` | образование и публикации |

Текстовые поля проходят через Markdown (`portfolio/richtext.py`): работают
ссылки, выделение и списки, голые адреса вида `https://…` превращаются в ссылки
автоматически. Многострочный текст записывается блоком `|`, иначе YAML склеит
строки в один абзац и разбиение на абзацы потеряется.

### Опыт работы

У записи опыта указываются машинные даты, а подпись периода и длительность
считаются в `portfolio/experience.py`:

```yaml
experience:
  - start: "2023-05"    # год-месяц, месяц можно опустить
    end: ""             # пусто означает «по настоящее время»
    role: "Должность"
    company: "Название компании"
    description: |
      Произвольный текст, поддерживает Markdown.
    highlights:
      - group: "Заголовок группы"
        items:
          - "Пункт списка"
```

Поле `highlights` принимает как простые строки, так и группы вида
`{group, items}`: строки подряд собираются в список без заголовка.

Месяц учитывается целиком, как на hh.ru: январь и февраль дают 2 месяца. Общий
стаж считается по объединённым интервалам, поэтому параллельные или
пересекающиеся места работы не удваивают его. Если вместо `start`/`end` задано
готовое поле `period`, оно выводится как есть и длительность не считается.

## Проекты

Один проект это папка `content/projects/<slug>/`, имя папки становится частью
URL. Внутри лежат `index.ru.md` и `index.en.md` с frontmatter, а также папка
`assets/` с изображениями и видео.

Обязательны только `title` и `category`, остальные поля опциональны.

| Поле | Значение |
|------|----------|
| `title` | название проекта |
| `category` | `python`, `shaders` или `other` |
| `summary` | описание для карточки на главной |
| `date` | `2025-06`, задаёт сортировку и подпись на карточке |
| `tags` | список меток |
| `tech` | стек, выводится отдельным блоком |
| `cover` | файл из `assets/`, обложка карточки на главной, кадрируется в 16:9 |
| `banner` | файл из `assets/`, широкая картинка шапки страницы проекта, около 3:1 |
| `featured` | поднимает проект в начало списка при равной дате |
| `theme` | оформление страницы, вешает класс `theme-<имя>` на `<body>` |
| `links` | кнопки-ссылки: `{label, url, icon}` |
| `gallery` | скриншоты: имя файла или `{src, caption}` |
| `video` | адрес для встроенного плеера в `<iframe>` |

`cover` и `banner` это разные файлы с разными пропорциями: без `banner` шапка
страницы проекта рисуется без картинки. Полный список полей с примерами описан
в шапке `portfolio/content.py`.

Проекты сортируются по дате от новых к старым, при равной дате выше идут
помеченные `featured`, затем сортировка по slug. Проекты без даты уходят в
конец списка.

Тело файла это обычный Markdown с расширениями `fenced_code`, `codehilite`,
`tables`, `toc`, `attr_list` и `smarty`. Допускается сырой HTML (`<iframe>`,
`<video>`, `<canvas>`) для видео и интерактивных вставок: содержимое пишет автор
сайта, поэтому оно считается доверенным и не вырезается.

Ссылки на файлы из `assets/` записываются от корня сайта:
`/projects/<slug>/assets/<file>`.

## Категории

Ключи категорий и порядок секций на главной задаются списком `CATEGORY_KEYS` в
`portfolio/content.py`. Человекочитаемые подписи берутся из раздела `categories`
в `content/translations/<lang>.yaml`. Добавление категории требует правки обоих
мест.

## Оформление

Общие стили лежат в `static/css/style.css`. Оформление отдельной страницы
проекта включается полем `theme` в frontmatter: значение `stars` вешает на
`<body>` класс `theme-stars`, правила для которого описаны в том же файле. Новое
оформление добавляется парой «значение `theme` плюс класс `theme-<имя>` в CSS».

## Статическая сборка

`freeze.py` рендерит сайт в набор готовых HTML-файлов:

```bash
python freeze.py                                      # собрать в ./build
python freeze.py --output dist                        # другая папка
python freeze.py --base-url https://user.github.io    # абсолютный URL для og-тегов
python freeze.py --force                              # очистить непустую папку сборки
```

В сборку попадают страницы всех языков, файлы проектов, `static/`, `404.html`,
`.nojekyll` и корневой `index.html` с переадресацией на язык по умолчанию (роут
`/` отдаёт редирект, который статикой не воспроизводится).

Файлы проектов копируются напрямую из `content/projects/*/assets`: пути к ним
записаны в шаблонах и в теле проектов вручную, а не через `url_for`, поэтому
обходом ссылок они не находятся. Дополнительно проверяется, не попали ли в
сборку указатели Git LFS вместо реального содержимого: в этом случае сборка
завершается с ошибкой.

## Публикация на GitHub Pages

Публикация описана в `.github/workflows/pages.yml`. Пуш в `master` или `main`
собирает сайт и деплоит его через GitHub Pages, дополнительно настроены ручной
запуск и ежемесячная пересборка по расписанию. В репозиторий коммитится только
исходный код: папка `build/` игнорируется, готовый сайт публикуется артефактом.

Условия, которые нужно учитывать:

- **Сайт должен размещаться в корне домена.** Пути к файлам проектов и к
  `static/` абсолютные, поэтому подходит репозиторий `<login>.github.io` или
  собственный домен. При публикации в подкаталоге вида `user.github.io/repo`
  ссылки на изображения и стили перестанут разрешаться.
- **Адрес сайта не задаётся вручную.** Action `configure-pages` возвращает его в
  `steps.pages.outputs.base_url`, значение передаётся в `freeze.py`. Параметр
  `enablement: true` включает Pages в режиме GitHub Actions, если это не сделано
  в настройках репозитория.
- **Git LFS.** Если изображения и видео хранятся в LFS, обязателен `checkout` с
  `lfs: true`, иначе вместо файлов опубликуются текстовые указатели. Каждая
  сборка расходует квоту трафика LFS.
- **Дата сборки.** Стаж в секции опыта считается от текущей даты, в статике он
  фиксируется на момент сборки. Для этого в workflow добавлена ежемесячная
  пересборка.
- **Лимиты GitHub Pages:** до 1 ГБ на сайт и до 100 МБ на файл.

## Развёртывание как WSGI-приложения

Встроенный сервер разработки для production не предназначен. Пример с gunicorn:

```bash
pip install gunicorn
FLASK_DEBUG=0 gunicorn -w 3 -b 127.0.0.1:8000 "app:app"
```

На Windows вместо gunicorn используется waitress:

```bash
pip install waitress
waitress-serve --listen=127.0.0.1:8000 app:app
```

Пример конфигурации nginx с проксированием и отдачей статики напрямую:

```nginx
server {
    listen 80;
    server_name example.com;

    location /static/ {
        alias /path/to/portfolio-site/static/;
        expires 7d;
    }
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
    }
}
```

## Переменные окружения

| Переменная | Назначение |
|------------|------------|
| `FLASK_DEBUG` | `1` для разработки (перечитывание контента), `0` для production (кэш в памяти) |
| `FLASK_SECRET_KEY` | секретный ключ Flask |
| `SITE_BASE_URL` | абсолютный URL сайта для тега `og:image`, например `https://example.com` |
